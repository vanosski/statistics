# Statistics Platform - Project Guide

## 1. Project Overview

**High-Level Purpose**
This project is a React-based web dashboard (Single Page Application) designed to visualize player and kingdom statistics. It uses Supabase as a backend data store and a suite of Python scripts for data processing, validation, and synchronization.

**Target Audience**
*   **End-Users**: Players, alliance leaders, and kingdom analysts looking to benchmark kingdom strength, view player rankings, and compare unit types.
*   **Developers**: Maintainers of the data pipeline and frontend interface.

**Core Features**
*   **Interactive Data Tables**: Dynamic filtering by server/kingdom and sorting across multiple statistical dimensions.
*   **Kingdom Benchmarks**: Top 10 kingdom average charts to compare kingdom strengths.
*   **Unit Strength Visualizations**: Breakdown of infantry, archer, cavalry, and siege stats.
*   **Automated Data Sync**: Python pipelines to process raw CSV/Excel data, convert it to static JSON for the frontend, and upsert detailed statistics into Supabase.

## 2. Architecture & Tech Stack

### Folder Structure Tree

```text
.
├── public/                 # Static assets
├── src/                    # React frontend source code
│   ├── components/         # React components (e.g., KdChartsSection.tsx, PlayerTable.tsx)
│   ├── data/               # Static JSON data generated by Python scripts (e.g., players.json)
│   └── lib/                # Library configurations (e.g., supabase.ts)
├── master_database.csv     # Source of truth for all player stats
├── package.json            # Node.js dependencies and scripts
├── vite.config.ts          # Vite configuration
├── build_json.py           # Python script to convert CSV data to JSON for frontend
├── sync_to_supabase.py     # Python script to upsert detailed data to Supabase
├── update_k27_local.py     # Data update script for Kingdom 27
├── fix_k27.py              # Utility script for fixing K27 data inconsistencies
├── parse_k27.py            # Parser for raw Kingdom 27 data
├── parse_k162.py           # Parser for raw Kingdom 162 data
├── remove_weakest_k162.py  # Data cleanup script for K162
├── del_oyku.py             # Script to handle specific player deletions
├── del_players.py          # Script to handle bulk player deletions
├── check_keys.py           # Utility to validate database keys
└── check_woc.py            # Utility to check specific alliance/WoC status
```

### Key Technologies

*   **Frontend**: 
    *   **React 19 & TypeScript**: Provides a robust, component-based UI architecture with type safety.
    *   **Vite**: A fast build tool and development server.
    *   **TailwindCSS / Vanilla CSS**: Used for styling the application.
    *   **react-chartjs-2**: A React wrapper for Chart.js to render interactive charts.
*   **Backend & Data**:
    *   **Python 3**: Used extensively for data wrangling, parsing CSV/Excel files, and acting as the ETL (Extract, Transform, Load) pipeline.
    *   **Supabase (PostgreSQL)**: Provides an instant API over PostgreSQL for robust data management and querying of detailed player statistics.

**Why these were chosen**:
React + Vite provides a fast, modern SPA experience suitable for data-heavy dashboards. Python is ideal for data manipulation and scripting from CSV sources. Supabase allows for quick deployment of a secure backend database without needing to write custom API routes.

## 3. Setup & Installation

### Prerequisites
*   **Node.js** (v18 or higher)
*   **npm** or **yarn**
*   **Python 3.x** (with pip)

### Step-by-Step Local Setup

1.  **Clone the repository** (if not already done) and navigate into the project directory:
    ```bash
    cd /path/to/coe/statistics
    ```

2.  **Install Node Dependencies**:
    ```bash
    npm install
    ```

3.  **Set up the Python Environment**:
    It is recommended to use a virtual environment.
    ```bash
    python3 -m venv venv
    source venv/bin/activate  # On macOS/Linux
    # pip install -r requirements.txt (if available, otherwise install required packages like requests, pandas if used)
    ```

4.  **Environment Variables Configuration**:
    Create a `.env` file in the root of the project with the following keys. These are required for the Supabase synchronization script to work.
    
    ```env
    VITE_SUPABASE_URL="your_supabase_project_url"
    SUPABASE_SERVICE_ROLE_KEY="your_supabase_service_role_key"
    ```
    *(Note: Ensure `.env` is added to `.gitignore` to prevent leaking secrets.)*

## 4. Running & Testing

### Development Server
To start the Vite development server with Hot Module Replacement (HMR):
```bash
npm run dev
```
*The app will typically be available at `http://localhost:5173`.*

### Building for Production
To compile the TypeScript and build the React application for deployment:
```bash
npm run build
```
To preview the built production bundle locally:
```bash
npm run preview
```

### Data Pipeline Execution
When player statistics are updated, run the following Python scripts in order:

1.  **Update Source Data**: (Example for K27)
    ```bash
    python update_k27_local.py
    ```
    *This script processes raw data and updates `master_database.csv`.*

2.  **Build Frontend JSON**:
    ```bash
    python build_json.py
    ```
    *This script reads `master_database.csv` and outputs `src/data/players.json`, which the React app imports directly.*

3.  **Sync to Supabase**:
    ```bash
    python sync_to_supabase.py
    ```
    *This script reads the newly generated JSON and upserts the detailed player statistics into the `players_detailed` table in Supabase.*

## 5. API & Core Logic Reference

### Data Flow
1.  **Raw Input**: Data is gathered from Excel (`Last_Land_Kingdom_Tracker*.xlsx`, `statsheetSenpai_populated.xlsx`) or manual inputs.
2.  **Processing**: Python scripts (`parse_*.py`, `update_*.py`) clean and format this data.
3.  **Source of Truth**: The cleaned data is written to `master_database.csv`.
4.  **Distribution**: 
    *   `build_json.py` extracts summary data for the fast-loading React frontend (`src/data/players.json`).
    *   `sync_to_supabase.py` pushes the full detailed data to the Supabase PostgreSQL database for deeper queries.

### Primary Modules

*   **`src/components/KdChartsSection.tsx`**: 
    *   *Purpose*: Core visualization logic for kingdom benchmarks. 
    *   *Key Functions*: Calculates the top 10 player averages per kingdom, sorts data dynamically (strongest to weakest), and renders the data using `react-chartjs-2`.
*   **`src/components/PlayerTable.tsx`**: 
    *   *Purpose*: Renders the main roster of players.
    *   *Key Functions*: Handles dynamic filtering by extracting unique server/kingdom IDs from the dataset and supports sorting by various stats.
*   **`sync_to_supabase.py`**: 
    *   *Purpose*: Handles the backend database synchronization.
    *   *Key Functions*: Uses the Supabase REST API (bypassing SSL verification for local Mac execution) to perform batch upserts (`on_conflict=name,server`) into the `players_detailed` table, ensuring data integrity without duplicating records.
*   **`update_k27_local.py`**:
    *   *Purpose*: A robust script for merging new kingdom data into the master database.
    *   *Key Functions*: It reads a specific CSV structure, formats percentages, calculates secondary stats (like Letal %), and merges the updates into `master_database.csv` while preserving players from other kingdoms.
